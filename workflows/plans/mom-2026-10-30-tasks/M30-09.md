# M30-09 — Đăng nhập email/mật khẩu

Nguồn: [MoM 30/10 §4]; mã task do TESO đặt.

Trạng thái: **ĐÃ TRIỂN KHAI LOCAL: email/mật khẩu, không role; có migration SQL**

Kế hoạch chi tiết cho giai đoạn phân quyền nằm tại [M30-09-rbac-plan.md](M30-09-rbac-plan.md). Flow đề xuất: Admin tạo role/chọn quyền → Admin tạo account/gán role → server hợp các quyền và kiểm tra từng request. Matrix chờ duyệt; chưa bật quyền theo role.

## Input

Người dùng chốt ngày 09/11: chỉ email + mật khẩu, chưa cần role. Mọi user đã đăng nhập có cùng quyền nghiệp vụ.

## Các bước

1. Đã thêm SnyUser và SnySession, SQL additive và rollback; áp SQL chỉ trên local.
2. Đã thêm scrypt, phiên 8 giờ, cookie HttpOnly và logout thu hồi phiên.
3. Đã bảo vệ tất cả handler nghiệp vụ, layout và Server Action lịch máy.
4. Đã thêm form login tiếng Việt và script tạo tài khoản local với mật khẩu nhập ẩn.
5. Đã kiểm tra local HTTP và browser; cần người dùng tạo tài khoản thật và UAT.

## Output

[Hướng dẫn và bằng chứng local](../../context/mom-2026-10-30/local-login.md); code auth; migration SQL; script create-local-user.ts và check-local-login.ts.

## Tiêu chí xong

Trang/API/action chặn người chưa có phiên; phiên hết hạn/logout không được dùng lại; mật khẩu được băm; sai 5 lần khóa tạm 15 phút. Phân role và quản trị tài khoản trên web chưa thuộc scope đã chốt.

## Vùng code/tài liệu cần đọc hoặc thay đổi

prisma; auth/session module; toàn bộ API/actions và layout. Đây là phạm vi dự kiến; card triển khai phải ghi file/hàm cụ thể sau thiết kế.

## Thông tin còn thiếu

Người dùng tạo email/mật khẩu thật qua script local. Chưa có yêu cầu reset mật khẩu, quản trị tài khoản web hoặc phân role; khi mở scope cần thiết kế bổ sung.

## Kiểm tra và rollback

Phân tích offline: truy vết tới file/sheet/ô, ghi rõ phạm vi chỉ đọc và phần chưa đối soát. Khi thay app: test vùng ảnh hưởng, typecheck và build theo gate repo. Thay DB dùng SQL additive có rollback; chỉ DB local đã xác minh. Giữ dữ liệu nguồn và liên kết cũ. Không QA bằng import production.
